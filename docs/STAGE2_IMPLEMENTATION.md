# Этап 2: окна как физические платформы

При старте выполняется `EnumWindows`. Затем события create, show, location,
minimize, hide и destroy обновляют только затронутое окно. Полная reconciliation
раз в пять секунд восстанавливает состояние после пропущенных событий и уточняет
z-order. Системный callback только помещает событие в очередь: он не меняет UI и
не касается физики.

## Коллизия

Во время `FALL` сохраняются предыдущая и новая нижние координаты. Resolver
выбирает ближайшую сверху поверхность между ними только при положительной
вертикальной скорости и горизонтальном пересечении foot interval. После
столкновения позиция точно ставится на поверхность, вертикальная скорость
обнуляется.

## Attachment

Хранятся platform id, относительная X-координата центра стоп, вертикальный offset
и последняя геометрия. При move мировая позиция вычисляется из новой геометрии
платформы без интеграции скорости окна, что устраняет дрожание. При resize
support проверяется повторно; исчезновение сегмента отправляет
`SupportLost → Fall`, сохраняя текущую мировую позицию.

## Ограничение перекрытий

Полная Win32 visible-region композиция пока не реализована. Консервативная
политика вычитает интервалы окон, расположенных выше по последнему известному
z-order и перекрывающих высоту поверхности. Компонент изолирован и покрыт
unit-тестом. Shaped и сложные layered regions могут оцениваться неточно.
